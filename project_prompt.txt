The product begins as a **web application** and is later expanded into native-quality applications for:

* Android

The application focuses on scientifically defensible cognitive training.

It must include training for:

* working memory,
* working-memory updating,
* verbal working memory,
* visuospatial working memory,

* reading efficiency / faster reading with maintained comprehension,

The application must NOT become a random collection of "brain games."

Every cognitive-training method must have scientific justification.

# FIRST PRINCIPLE: EVIDENCE BEFORE FEATURES

The application may include only cognitive-training methods supported by credible research or explicitly presented as experimental.

Before implementing each training method:

1. Search current research.
2. Evaluate evidence quality.
3. Separate trained-task improvement from transfer.
4. Identify the studied population.
5. Identify limitations.
6. Add the result to the evidence registry.
7. Only then decide whether the exercise belongs in production.

Prioritize:

1. systematic reviews,
2. meta-analyses,
3. randomized controlled trials,
4. preregistered studies,
5. replication studies,
6. established experimental paradigms.

Do not rely on marketing claims from commercial brain-training companies.

---

# SCIENTIFIC HONESTY

Never automatically claim that training:

* increases IQ,
* makes someone generally smarter,
* prevents dementia,
* cures ADHD,
* treats neurological disorders,
* permanently increases intelligence,
* guarantees improvements in school/work performance.

Distinguish clearly between:

## Training gains

Improvement on a task the user practices.

## Near transfer

Improvement on different tasks using similar cognitive processes.

## Far transfer

Improvement on substantially different cognitive abilities or everyday outcomes.

These categories must remain separated throughout:

* research,
* database,
* analytics,
* progress UI,
* marketing copy.

---

# EVIDENCE SCALE

Use a transparent scale such as:

**Strong**

Several high-quality studies/reviews with reasonably consistent results.

**Moderate**

Credible positive evidence exists, but effects may be modest or inconsistent.

**Limited**

Evidence exists but has substantial uncertainty.

**Experimental**

Interesting research exists but efficacy has not been established.

**Unsupported**

Do not use as cognitive training.

# FAST READING / READING EFFICIENCY TRAINING

Add a major training category:

# Reading Training

The objective is NOT:

"read impossibly fast."

The objective is:

**increase reading efficiency while maintaining adequate comprehension.**

`reading speed`

`reading comprehension`

Never reward WPM increases if comprehension deteriorates significantly.

---

# RESEARCH FAST-READING CLAIMS FIRST

Before implementing reading exercises, review scientific research concerning:

* reading rate,
* reading comprehension,
* perceptual span,
* eye movements,
* regressions,
* subvocalization,
* lexical processing,
* reading expertise,
* text difficulty,
* RSVP,
* paced reading,
* skimming,
* previewing,
* chunking,
* comprehension monitoring.

Investigate which techniques genuinely improve reading efficiency and which "speed reading" techniques are unsupported.

Do not implement common speed-reading myths simply because they are popular.

---

# IMPORTANT READING SCIENCE PRINCIPLE

Reading speed and comprehension commonly involve a trade-off.

Therefore never show:

**Your reading improved by 80%.**

based purely on WPM.

Instead calculate and show both.

Example:

Previous:

`246 WPM`

`88% comprehension`

Current:

`281 WPM`

`89% comprehension`

This could represent meaningful progress.

But:

`450 WPM`

`43% comprehension`

must NOT be treated as superior performance.

---

# READING EFFICIENCY SCORE

If creating a combined reading metric, make the formula transparent.

It should incorporate:

* reading speed,
* comprehension,
* text difficulty,
* sufficient question count,
* measurement reliability.

Never allow extreme speed to compensate entirely for poor comprehension.

Consider requiring a comprehension floor.

For example:

speed gains only count fully when comprehension remains above an evidence-informed threshold.

Do not hardcode an arbitrary threshold without reviewing research.

---

# READING TRAINING EXERCISES

Research before deciding which ones to retain.

Possible candidates include:

## Paced Reading

A visual guide gradually increases reading pace.

The user reads normally while pacing increases.

After reading:

comprehension questions.

Difficulty adapts only when comprehension remains adequate.

## Adaptive Reading

Determine a current comfortable pace.

Gradually increase it.

If comprehension declines:

reduce pace or difficulty.

If comprehension remains strong:

increase challenge.

## Text Chunking Training

Where scientifically justified, help users practice processing meaningful groups of words rather than visually treating every word as isolated.

Do not claim this eliminates normal eye movements.

## Information Extraction

Ask the reader to identify:

* thesis,
* main idea,
* supporting arguments,
* important details,
* conclusions.

This prevents speed training from becoming superficial scanning.

## Skimming Training

Teach when fast skimming is appropriate.

Measure whether the user can quickly identify:

* structure,
* relevant section,
* key arguments.

Clearly distinguish:

**skimming**

from:

**full comprehension reading.**

## Reading Flexibility

Teach users that good readers do not always read at the same speed.

Different goals require different strategies.

For example:

Novel

→ normal reading

Technical documentation

→ slower analytical reading

Search for one fact

→ scanning

Article overview

→ skimming.

Teach **adaptive reading**, not maximum speed at all costs.

# GAMIFICATION MONETIZATION RULE

Never intentionally make scientifically useful training ineffective unless a user pays.

Premium should primarily unlock:

more personalization,

more content,

analytics,

advanced modes,

convenience,

customization.

Avoid:

"Your memory score is hidden until you pay."

# A/B TESTING

Later phases can test UX elements such as:

onboarding length,

daily-plan presentation,

achievement timing,

paywall design.

Never A/B test scientifically different training algorithms and silently treat results as equivalent.

Track task versions.

---

# TASK VERSIONING

Every scientific task must have versions.

Example:

`visual-nback-v1.3`

If stimulus logic or scoring changes, old performance remains attached to the old version.

Do not silently compare incompatible versions.

# UX TESTING

Testing code is not enough.

Create usability-testing scenarios.

Examples:

"Start your first training session."

"Choose an easier level."

"Find your reading progress."

"Change your daily goal."

"Find the science supporting this exercise."

"Cancel a subscription."

A new user should complete these without instruction whenever reasonably possible.

---

# PERFORMANCE

The app must feel fast.

Targets should be defined for:

page load,

interaction response,

route transitions,

exercise startup.

Preload the next exercise where appropriate.

Avoid loading large dashboard dependencies during an active training task.

---

# SCIENTIFIC PROGRESS LANGUAGE

Good:

"You reached a new personal best on this spatial-memory task."

Good:

"Your reading pace increased while comprehension remained stable."

Good:

"Performance improved on the trained task."

Not acceptable:

"Your brain is now 17% stronger."

Not acceptable:

"Your IQ increased."

---

# INITIAL PRODUCT SUCCESS CRITERIA

The WEB application succeeds when a user can:

create an account,

use email/Google/Facebook authentication,

finish onboarding quickly,

intuitively choose or accept recommended training level,

complete evidence-supported working-memory exercises,

complete reading-efficiency training,

receive adaptive difficulty,

complete daily training,

see understandable progress,

inspect research supporting each exercise,

return across multiple days,

earn legitimate achievements,

understand the difference between training gains and transfer,

use the application comfortably on desktop and mobile browsers.

---

# MOBILE SUCCESS CRITERIA

Mobile phase succeeds when the same user can:

install iOS or Android app,

log into the same account,

see synchronized progress,

complete training,

receive high-quality native interactions,

use optional reminders,

earn the same achievements,

continue training seamlessly across web and mobile.

# PRIORITY ORDER WHEN MAKING TRADE-OFFS

Use this order:

1. Scientific integrity
2. Excellent UI/UX
3. User comprehension
4. Training engagement
5. Core functionality reliability
6. Accessibility
7. Performance
8. Maintainable architecture
9. Gamification
10. Additional feature count

Never sacrifice the first five to ship more exercises.

# FINAL RULE

The ultimate product should NOT feel like:

"a scientific experiment users tolerate."

It should feel like:

**a premium, enjoyable training product whose science happens to be unusually rigorous.**

Users should understand what to do immediately.

Training should be challenging enough to feel meaningful.

Progress should feel rewarding.

Gamification should encourage healthy consistency.

Reading training should improve efficiency without sacrificing comprehension.

Scientific claims must remain defensible.

UI and UX quality must be exceptional.

Build the product accordingly.
